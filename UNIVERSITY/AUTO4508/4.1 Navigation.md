# Wandering Standpoint Algorithm
- Local path planning algorithm
- Local information: Local distance sensor
- Try to reach goal from start in direct line. When encountering an obstacle, measure avoidance angle for turning left and for turning right, turn to smaller angle. Continue with boundary-following around the object, until goal direction is clear again

# Bug Algorithm Family
- Algorithms combining local planning with global information, guarantees convergence
- Local information: local sensor data plus global information
- Bug, Bug2, DistBug, TangentBug
```
S = starting pos
T = Target pos
H_i = ith hit point. The first pnt of contact between robot and i obstacle
L_i = ith leave point. Pnt where robot leaves i obstacle
x = robots current position
d(a, b) = Euclidean dist between a and b
d_path(a, b) = Path length between a and b
F = Freespace in target direction
min_dist = min dist to goal during border following
STEP = min improvment over prev shortest dist
```
### Bug1 
1. Initialise $i=0$
2. Increment $i$ and move toward target until one of the following occurs:
	1. The target is reached. Stop.
	2. An obstacle is encountered. Label $H_i$ and proceed.
3. Keeping obstacle on the right, follow the obstacle boundary. Whilst doing so, record the point where $d(x, T)$ is minimal. Label this point $L_i$. Do this until one of the following occurs:
	1. Point $H_i$ is reached. Proceed.
	2. The target is reached. Stop.
4. Test whether the target is reachable
	1. To do this, check if $H_{i}= L_{i}$. If so, the target is unreachable. Stop.
	2. Otherwise, choose the wall-following direction, which minimises $d_{path}(H_{i}, L_{i})$ and manoeuvre to $L_{i}$. At $L_{i}$, proceed to step 2.

### Bug2
1. Initially, plot imaginary, $M$, directly from start to target (does not extend beyond those points) and initialise $i = 0$ 
2. Increment $i$ and follow the $M$ line towards the target until either:
	1. The target is reached. Stop.
	2. An obstacle is hit. Label this point $H_i$. Proceed.
3. Keeping the obstacle on the right, follow the obstacle boundary. Do this until:
	1. A point along $M$ is found such that $d(x, T) < d(H_{i}, T)$. Label this as $L_{i}$. Go to 2.
	2. The target is reached. Stop.
	3. The robot returns to $H_{i}$. The target is unreachable.

### DistBug Algorithm
- Algorithm combining local planning with global information, guarantees convergence.
- Local sensor data positioning.
- Similar to wandering standpoint algorithm, but boundary-following stops only if goal is directly reachable or if future hit-point with next obstacle would be closer to goal. This information together with detection of unreachable goal if robot has turned $360degrees$ guarantees convergence. Although this algorithm has very nice theoretical properties, it is not always usable in practice because the required positioning accuracy may not be achievable. 
1. Initialise $i=0$ and $STEP$
2. Increment $i$ and move toward target until:
	1. Target reached. Stop
	2. Obstacle hit. Denote as $H_i$. Proceed. 
3. Turn left and follow the obstacle boundary whilst continuously updating freespace to target `F` and minimum value of `d(x, T) = d_min(T)`. Repeat until:
	1. Target is reached. Stop
	2. Target is visible. Mark this point as $L_i$ go to step 2.
	3. A position closer to the goal can be reached. Mark this point as $L_{i}$, go to step 2
	4. The robot reached $H_{i}$, target is unreachable. Stop

**Line-Square Intersection**
1. Are all corners of box $RSTU$ on same side of line $A-B$? Then no intersection.
2. Else, project line endpoints on $x, y$ axes and check if line shadows overlap square shadows on both
$$
F(P) = (B_{y}-A_{y})\times P_{x}+ (A_{x}-B_{x})\times P_{y}+ (B_{x}A_{y}- A_{x}B_{y})
$$
- F(P) = 0 means P is on line AB
- F(P) > 0 means point P is above line
- F(P) < 0 means below
- If all four Fs are positive or all negative, then there is no intersection

# Voronoi Diagram
- Find "Skeleton Points" of free-space area
- $F$ = Free space in environment
- $F'$ = Occupied space
- $b \in F'$ is basis point for $p \in F$ $iff$ it has minimal distance to $p$
- Voronoi diagram $= \{p\in F | pHas>2BasisPoints\}$
- Usage:
	- Extracts structure from environment
	- Skeleton of environment
	- Can be used for generating graph nodes

### Delaunay Triangulation
- $q_{1}, q_{2}, q_{3} \in F'$ form the triangle $iff$ there is $p \in F$ that is equidistant to the $q$s and no other point in $F'$ is nearer to $p$. Point $p$ is then a Voronoi Point
- This means $p$ is centre of circle touching $q$s and without any other point of $F'$ inside it
- Corners in $F'$ are also Voronoi Points
- Use points as graph nodes for navigation algorithm or join neighbouring Voronoi points with lines

# Brushfire Algorithm
- Simple algorithm for generalised Voronoi diagrams in Occupancy grid
- Use Occ Grid
- Identify each obstacle and border with a unique label/colour
- Iteration (`i = 2; noMoreChange; i++`)
	- If a free pixels neighbours (4 nearest or 8) a labelled pixel then label it `i` in the same colour
	- If a free pixel is being overwritten twice in different colours, it is a Voronoi point
	- If a free pixel and its top or right neighbour have been overwritten with `i` in different colours, then it is a Voronoi point.

# Dijkstra's Algorithm
- Computes all shortest paths. Time complexity is $O(e+v^{2})$ and can be reduced to $O(e + vlogv)$
- Requires relative distance information between all nodes, cannot be negative
- Start ready set with start node, loop over all remaining nodes; select closest node and update shortest distances to nodes in ready set, record predecessor, add current node to ready set. Loop finishes when all nodes in ready set
1. Initialise start distance to 0, others to infinite `dist[s]=0, dist[i] = inf (for i != s)`, set `Ready = {}`
2. Loop until all nodes are in Ready{}
	1. Set node `n` with shortest distance that is not in Ready{} 
	2. `Ready = Ready + {}`
```python
for eachNeighbour m of node n:
	if dist[n]+edge(n, m) < dist[m]:
		dist[m] = dist[n] + edge(n, m);
		pre[m] = n;
```

# A* Algorithm
- Heuristic algorithm for computing the shortest path from one given start node to one given goal node. Average time complexity is $O(klog_{k}v)$ for $v$ nodes with branching factors $k$ but can be quadratic in worst case
- Requires global information; relative distance information between all nodes plus lower bound distance to goal from each node
- Maintain sorted list of paths to goal, in every step expand only the current shortest path by adding adjacent node with shortest distance to goal
