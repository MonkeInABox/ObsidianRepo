- Two types, ROS1 and ROS2
- Built for Linux - Ubuntu
- Code can be C++ or Python
- Key concepts
	- Nodes - individual code created to achieve a task
	- Various messaging services
	- Transforms
# Why ROS?
- When developing software
	- Development time
	- Implementing base features
	- Setting up sockets
	- Creating drivers
- This is time consuming and expensive
- ROS allows for fast development and is an open source tool

# Overview
## Nodes 
- Programs that communicate using
	- Topics (continuous data)
	- Services (request/response)
	- Actions (long running tasks)
## File System Organisation
```
workspace/
	src/
		{c++ pkg node 1 dir}/
			package.xml
			CMakeLists.txt
			src/
				{code}
		{python pkg node 2 dir}/
			package.xml
			setup.py
			{package name (convention)}/
				{code}
	build/
	install/
		{where the built code sits}
	log/
```
SIMPLEST:
```
packageName/
	package.xml
	CMakeLists.txt (or setup.py)
	src/ (nodes definition)
	include/ (headers)
	launch/ (files to launch application)
	config/ (yaml and other config files in nodes and launch)
	maps/ (saved maps for driving)
	models/ (all robot and world model files)
		meshes/
		worlds/
		robots/
	rvix/ (config for rviz)
```

## Creating a Workspace
```
$ mkdir ros_workshop_ws
$ mkdir ros_workshop_ws/src
$ source /opt/ros/humble/setup.bash

$ ros2 pkg create --build-type <ament_python or ament_cmake> --license Apache-2.0 --node-name my_node my_package
```

## Create a Node
```c++
int main(int argc, char **argv) {
	rclcpp::init(argc, argv);
	auto new_node = std::make_shared<rclcpp::Node>("new_node");
	rclcpp:spin(new_node); //run indef
	
	return 0;
}
```
- CMakeLists.txt
```
add_executable(new_node/new_node.cpp)
ament_target_dependencies(new_node <dependencies)
install (TARGETS new_node DESTINATION lib/${PROJECT_NAME})
```

## Building the System
- First specify where to find ROS install
- ROS2 uses `colcon build`
- Can build individual packages using `--packages-select {pkg_name}`
- For python use `--symlink-install`
- Look through the source folder for package.xml files to create the nodes

## Running
`$ ros2 run `
`$ ros2 launch` runs all nodes in launch file
- Keep systems separate using `ROS_DOMAIN_ID`
	- `export ROS_DOMAIN_ID=12`

## Launch file
```python
from launch import LaunchDescription
from laun_ros.actions import Node

def generate_launch_description():
	return LaunchDescription([
		Node(
			package='pkgname',
			executable='newNode',
			name='nodeName'
		),
	])
```
- We can give nodes unique names

## Publisher/Subscriber
- Each node creates its own publisher which starts a new topic to send messages to

## ROS2 Parameters
- Parameters configure node behaviour at runtime
- Common uses:
	- Robot configuration values
	- Controller tuning
	- Feature toggles
- Commonly stored in YAML files
```YAML
controller:
	max_speed: 1.0
	wheel_radius: 0.15
```
- Easy configuration

## Transforms
- Static non-moving transforms (between robot base and sensor)
- Dynamic - moving transforms (between map and robot as it moves)
- 3 transforms required for autonomous driving
	- base or base-link
	- map frame
	- Odom (local motion estimate)
- It is important to transform your sensors relative to their location on the base robot so the incoming data is correct
