# PLC Design Problem
- Design a controller to maintain the water level in a tank between two limits. The water should not go below a low level point called "Low" and should not exceed a height called "High". The level of water can be increased using an electric pump. A limit switch will close when the water level is below "Low" and another limit switch will close when the water level is above the height "High". Otherwise both limit switches are open.

# Timers and Counters
- Output instructions that let you control operations based on time or a number of events
```
TON = Timer, On Delay = Delay turning on an output on a true rung
TOF = Timer, Off Delay = Delay turning off an output on a false rung
RTO = Retentive Timer On = Delay turning on an output on a true rung, accumulator is retentive
CTU = Count up
CTD = Count down
RES = Reset = Reset the RTO
```

# Controller Design Using Ladder Code
- Using a Finite State Machine as a design model has the following advantages:
	- Efficient development: scaffold ensures important items are not forgotten, makes it methodical and documentable
	- Predictability: easy to understand
	- Troubleshooting
	- Reducing complexity
	- Compatibility
## FSM
- 5 elements
	- Finite set of states, one initial
	- Finite set of external inputs
	- Finite set of external outputs
	- Set of rules that determine all state transitions
	- Set of rules that determine all outputs (only current state = Moore, current state and input = Mealy)
- A state transition Graph (STG) has:
	- Nodes
	- Edges
- A deterministic finite-state machine can be represented by 6-tuple $A = (Q, \Sigma, \Delta, \sigma, \lambda, q_{0})$
	- $Q$ is set of states
	- $\Sigma$ is the input alphabet
	- $\Delta$ is the output alphabet
	- $\sigma$ is the state transition function
	- $\lambda$ is the output function
	- $q_{0}\in Q$ is an initial state

![[Pasted image 20260310100719.png]]
- This ensures only one state is active at a time
- It is clear what inputs cause the state change
- It is clear what outputs are provided for each state
## Analysis
- The analysis of a PLC is to define the functionality by a FSM $A$ 
	- Each state $Q$
	- Initial state $q_0$ 
	- Inputs $\Sigma$
	- Outputs $\Delta$ 
	- Computing truth tables for $\lambda$ and $\sigma$ 
	- Define Boolean functions according to truth tables
## Synthesis 
- Given $A$ design a PLC as follows
	- Allocate output memory addresses to each state $Q$
	- Define initial state $q_{0}$
	- Allocate memory addresses for each $\Sigma$ 
	- Allocate memory addresses for each output $\Delta$ 
	- Compute truth tables (Karnaugh) for the functions $\lambda$ and $\sigma$

## Yoghurt Processing Example
- Low pasteurised (milk raised to 72 degrees C for 15 seconds) and homogenised milk be high pasteurised (raised uniformly to 86 degrees C for 25 minutes)
- Uniformly cooled to 45 degrees C in the preparation tank
```
Preparation Tank: (86degC, 25m) -> (45degC), always uniformly
```
![[Pasted image 20260311085252.png]]
$A = (Q, \Sigma, \Delta, \sigma, \lambda, q_{0})$
- $Q =$ Starting, Started, Filling, Heating, Timing, Cooling, Emptying, Resetting, Idle, Fault, Stopping, Stopped, Suspended
- $\Sigma =$ LL, HL, <45, >86, Stop, Start, Suspend, Reset, 25 mins
- $\Delta =$ Fill, Heat, Stir, Cool, Empty, Fault, Started, Suspended, Stopped, Idle, Complete
- $\sigma: q\times \Sigma \to Q$
- $\lambda: Q \times \Sigma \to \Delta$
- $q_{0}=$ Idle

### Assumptions
- **interlocks** there are a number of conditions that should not happen. 
	- The input valve cannot be open when the output valve is open and vice-versa
	- The heater cannot be on when the cooler is on and vice-versa
	- The stirrer is on when either heater or cooler are on
	- The stirrer, heater or cooler cannot be on if the tank level is less than HL
	- The stirrer, heater or cooler cannot be on if IV or OV are not closed
### Fault Detection
- There are a number of conditions that cannot happen in reality and hence can be used in fault detection
	- Both HT and LT are true
	- Both HL and LL are true
